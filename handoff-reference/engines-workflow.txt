# Style Actions Engine Layer — Specification

_9 Oct 2026 · Loukit Kumar_

Status: draft for review. Parent: `docs/spec-inputs/engine-logic-flows.md` (the engine bible). Builds on Scope 2 (`docs/scopes/scope-2-health-space-dc.md`). Logic source: Style Actions spec v2, readiness baseline `docs/spec-inputs/engine-readiness-2026-10-03.md`.

---

## 1. Outcome

After the engine layer is built, on existing snapshot data:
- a **nightly engine run** evaluates every Fashion and Ultimate option × store through the rule tree (Gates 0–4) and produces action lines: replenishment, pullback (broken/consolidation/overfill/lifecycle-end/replacement), markdown, or hold;
- each action line carries its **full decision trace**: which gate decided, what metrics drove the decision, which settings version applied;
- a **settings cascade** resolves 38 configurable parameters through a 10-level hierarchy so every threshold is traceable and overridable;
- **Temporal** orchestrates the run: strict sequencing (replenishment before pullback), per-DC parallelism, timers for review windows, signals for human approvals;
- **Phase 0 (shadow)** runs engines against existing snapshots with no execution — record-only, for validation against historical ANR outputs;
- the UI scope document (`impetus-agentic-prototype/docs/specs/style-actions-engine-scope.md`) describes how these outputs surface in the frontend.

**Not in this spec:**
- Live execution (STO dispatch via Procuro/SAP, CPE price changes) — Phase 2;
- VMI interlocks for Core — Phase 2;
- Test & Scale — Phase 3;
- Outcome measurement and calibration — Phase 4;
- Frontend implementation — separate spec in `impetus-agentic-prototype`.

## 2. Phasing

| Phase | Engine scope | Execution mode | External data needed | Milestone |
|---|---|---|---|---|
| **0 — Shadow** | All engines run against existing snapshots | Record-only: lines written to DB, no files, no STOs | None. Gate 3 → "not evaluated". Gate 4 → provisional if no cost data. Concentration → "not evaluated", all markdown → stop-and-approve | Compare engine outputs against historical ANR recommendations |
| **1 — File mode** | Same engines, live nightly snapshots | CSV export (replenishment, pullback, markdown files) with line contract | Cost/margin feed (N1), current price feed (N12) | Pilot with category team reviewing files |
| **2 — Live** | Same engines + VMI interlocks | Direct STO (Procuro/SAP) + CPE price changes + read-back reconciliation | All of Phase 1 + VMI feed + rail health values (N2) + concentration values (N5) | Automated execution with governance |

Phase 0 validates by running against existing snapshots (e.g. `snap_legacy_0922`, snapshots built for S3KG + V012) and comparing outputs against the ANR baseline tables (`analytics_planning.impetus_planning_anr_*`). No new BigQuery cost.

### 3.2 Immutability rule

The engine never writes to snapshot tables. It reads from them (option_store_measure, option_health, stock_size, dc_stock_size, space_fill, lead_time, planogram, store, sales_line, option_size_day) and writes only to its own `engine_*` tables. A snapshot can be used by many engine runs; an engine run reads exactly one snapshot.

## 6. Engine logic

### 6.1 Line state machine

```
[*] ──► Proposed
          │
          ├── (replenishment, auto-band markdown) ──► Released
          │
          └── (pullback, stop-and-approve markdown) ──► InReview
                │
                ├── (window ends unblocked / approved) ──► Released
                ├── (block upheld by Head of F&L) ──► Blocked ──► Held
                └── (approver rejects) ──► Rejected ──► [*]
                                                          
Released ──► AcceptedDownstream
              │
              ├── ──► InTransitOrApplied ──► ReceivedOrPriced
              │                                │
              │                                ├── (match) ──► Reconciled ──► [*]
              │                                └── (differ) ──► Mismatch ──► [*]
              │
              └── (STO not processed in 72h) ──► Expired ──► [*]

Blocked ──► Held ──► [*]
```

Phase 0 (shadow): lines are written as `Proposed` then immediately marked `shadow_recorded`. No state transitions beyond that.

### 6.2 Replenishment engine (nightly)

**Input:** snapshot measures (option_store_measure, option_health, stock_size, dc_stock_size, lead_time, space_fill).

**Eligibility per option × store:**
1. Grade is Fashion or Ultimate (Core → VMI, skipped)
2. Live at store: option_store_measure.on_hand > 0 or option_store_measure.transit > 0 (the option has saleable or in-transit stock at this store)
3. Lifecycle age (F16) ≤ `repl_window_day` (default 60)
4. Not on a pending or held pullback line (check engine_line)
5. Not marked down (check option_state.is_marked_down) — except size-completion (C13)

**Target per option × store (F10):**
```
target = ceil(max(true_ros_daily × (lead_time_days + 1), len(pivotal_sizes)))
```

**Capacity cap per store × brick × grade:**
1. Sum targets of replenished options + inventory position of non-replenished options
2. If sum > space_plan_qty (F8): sort replenished options by True ROS ascending, cut lowest first, never below pivotal-size count

**Size split (F11):**
1. Each pivotal size gets 1 unit base
2. Remainder = target − pivotal count
3. Each pivotal size's share = its eligible_units / total eligible_units
4. Raw allocation = remainder × share, floored
5. Leftover units to largest fractional remainders (tie-break: size code)
6. Dispatch per size = max(0, size_target − inventory_position_for_size)

**DC rationing (when DC stock < total dispatch for an article):**
1. Rank stores by gap ascending (furthest ahead first); supply-constrained and under-min-age rank as gap 0; tie-break True ROS desc then store code
2. Pass 1: each store gets 1 unit of its largest-shortfall pivotal size
3. Pass 2: fill remaining dispatch, size by size, until DC stock runs out

**Output:** replenishment lines in engine_line, type `replenishment`, status `Proposed` then immediately `Released` (no review).

### 6.3 Rule tree (Gates 0–4, nightly)

**Input:** snapshot measures, option_state, cost_margin, current_price.

**Evaluated per option × store, Fashion and Ultimate only (C15: Core excluded).**

**Gate 0 — Eligibility:**
- G0a: lifecycle_age ≥ `exit_day` (90) → outcome `liquidation`
- G0b: days_in_store < `min_age_days` (14) → outcome `wait`

**Gate 1 — Performance:**
- True ROS unmeasurable → outcome `wait` (never judged behind)
- Supply-constrained (band) → outcome `supply_hold`
- Band Over or On-track → outcome `leave_alone`
- Band Watch or Under → behind, continue

**Gate 2 — Move feasibility (all sub-gates must pass):**
- G2a: a destination store in the same DC cluster is selling this option and is below space plan for that brick × grade (simplified feasibility check; the full DC demand F12/F13 is computed later inside the pullback engine)
- G2b: remaining life to day 90 minus `transit_days` ≥ `runway_min_days`
- G2c: option_state.pullback_count < `pullback_cap` AND (last_pullback_date is NULL or run_date − last_pullback_date ≥ `cooldown_days`)
- All pass → outcome `move`
- Any fail → continue

**Gate 3 — Local rail health:**
- Thresholds missing (N2) → gate_3 = `not_evaluated`, continue to Gate 4 with outcome routed to stop-and-approve
- Rail healthy → outcome `hold`
- Rail dead → continue

**Gate 4 — Margin headroom:**
- Already marked down (option_state.is_marked_down) → outcome `discount` (ladder progression via markdown engine)
- lifecycle_age < `markdown_start_day` (60) → outcome `hold` (no early markdown)
- cost_margin row missing → gate_4 = `not_evaluated`, outcome `hold` (provisional)
- current_price row missing → gate_4 = `not_evaluated`, outcome `hold` (provisional)
- Headroom = current_price − margin_floor: if ≤ 0 → outcome `hold_to_exit`
- Headroom > 0 → outcome `discount`

**Output:** gate_result rows. MOVE outcomes are queued as nominations for the next pullback run. DISCOUNT outcomes feed the markdown engine. All other outcomes are observation-only.

### 6.4 Pullback engine (Monday and Thursday, after replenishment)

**Input:** snapshot measures, gate_result (move nominations), dc_demand, option_state, post-replenishment DC stock.

**DC demand and shortfall per article × DC (F12, F13):**
```
For each eligible store (option live, lifecycle_age ≤ 60):
  contribution = max(0, true_ros_daily × (lead_time + cover_days) − inventory_position)

demand = Σ contributions
shortfall = max(0, demand − dc_stock_post_replenishment)
```

**Pullback types, in fixed order per article × DC:**

**1. Broken size set (F14):**
- Trigger: broken_pct > `broken_threshold` (50%) OR (`broken_pivot_out` AND a pivot size has zero inventory position)
- Not limited by shortfall
- Destination: highest-STR store in DC cluster selling the option
- Space floor check applies
- Pull full option from donor to DC; DC rebuilds one complete pivotal set and sends to destination
- Decrement shortfall by qty pulled + donor's demand contribution

**2. Consolidation:**
- Runs only while shortfall > 0
- Candidates: Underperforming, or Watch at lifecycle day ≥ 60, or Core past min age
- Exclude: Supply-constrained, Over, On-track, marked-down, lifecycle ≥ 90
- Rank: Fashion/Ultimate gap desc (tie oldest stock); Core weeks_of_cover desc (tie oldest)
- Space floor check applies
- Pull full option, donor → DC → destination
- Decrement shortfall; stop when shortfall ≤ 0

**3. Overfill:**
- Trigger: options_fill > `overfill_threshold` (120%) OR units_fill > `overfill_threshold` (120%)
- Not limited by shortfall
- Sort: oldest first by whole weeks in store, then highest weeks_of_cover, then option_code
- Space floor check applies (C11: stop at floor)
- Pull until both fills ≤ 120%

**4. Lifecycle-end:**
- Trigger: first pullback run at lifecycle_age ≥ `exit_day` (90)
- Fashion and Ultimate only (Core: never)
- Floor ignored
- Full option → DC → Fashion Factory
- Human confirms exit batch (governance trigger)

**5. Replacement (after pulls):**
- Trigger: store × brick × grade now below space plan after pulls
- Fashion and Ultimate only
- Candidate: matching segment/family/class/brick/grade, complete pivotal set at DC, not already live at store, lifecycle ≤ 60
- Linked to pullback line: released together, held together

**Output:** pullback lines in engine_line (types: `broken`, `consolidation`, `overfill`, `lifecycle_end`, `replacement`). All enter `InReview` with a 12-hour review window.

### 6.5 Markdown engine (nightly, from day 60)

**Input:** gate_result (DISCOUNT outcomes), option_state, cost_margin, current_price.

**For each option × store with outcome `discount` or option_state.is_marked_down:**

1. **Check prerequisites:**
   - current_price row exists → if not, exclude, reason `missing_price` (N12)
   - cost_margin row exists → if not, exclude, reason `missing_cost` (N1)
   
2. **Compute (F18–F22):**
   ```
   blended_cost = base_cost + taxes + cost_buffer          (F18)
   margin_floor = blended_cost + category_margin            (F19)
   headroom = current_price − margin_floor                  (F20)
   ```
   - Headroom ≤ 0 → hold to exit, no markdown line

3. **Determine tier (F21):**
   - lifecycle_age in [60, 74] → tier 1, depth = `ladder_tier_1_depth` (10%)
   - lifecycle_age in [75, 79] → tier 2, depth = `ladder_tier_2_depth` (20%)
   - lifecycle_age in [80, 89] → tier 3, depth = `ladder_tier_3_depth` (25%)
   
4. **Check tier progression:**
   - Already marked down at same tier → no new line (price already at this tier)
   - New tier → proceed

5. **Compute marked price (F22):**
   - Cumulative depth off the pre-markdown reference price (C14)
   - `marked_price = max(reference_price × (1 − depth), margin_floor)`
   - If floor binds: flag `floor_binding`

6. **Concentration checks (run-level):**
   - Brick concentration: lines covering > `concentration_brick_pct` (15%) of brick's live inventory value → T4
   - Category concentration: > `concentration_category_pct` (20%) of category's options in `concentration_window_days` (7d) → T5
   - Rupee cap: if `concentration_rupee_cap` is set and event value exceeds it → T6
   - If any threshold is NULL → `not_evaluated`, all markdown lines → stop-and-approve

**Output:** markdown lines in engine_line, type `markdown`. Auto-band → `Released`. Stop-and-approve → `InReview`.

### 6.6 Governance routing (T1–T7)

Each line is classified into an autonomy band after computation:

| Band | Criteria | Action |
|---|---|---|
| **auto** | Replenishment; Fashion markdown within ladder, above floor, ≥ day 60, no concentration breach | Released immediately |
| **review_window** | Pullback and replacement lines | 12-hour window, block-only |
| **stop_and_approve** | Floor binds (T1); early markdown (T2); Core/Ultimate event (T3); brick concentration (T4); category concentration (T5); rupee cap (T6); manual price (T7); Gate 3 not_evaluated; any concentration check not_evaluated | Held until approver decides |
| **manual** | Liquidation batch confirmation | Human confirms |

### 6.7 Execution dispatch

**Phase 0 (shadow):** lines stay at `shadow_recorded`. No files generated.

**Phase 1 (file mode):** generate CSV files per line type:
- `replenishment_{run_id}.csv`: source_dc, dest_store, article, size, quantity
- `pullback_{run_id}.csv`: source_store, dest_dc, article, quantity, type, reason
- `markdown_{run_id}.csv`: store, option_code, current_price, marked_price, depth, tier, reason

File contract matches the engine bible §17 line contract.

## 7. Temporal workflow design

### 7.1 NightlyEngineWorkflow

```python
@workflow.defn
class NightlyEngineWorkflow:
    """Top-level workflow: one per org per night."""

    @workflow.run
    async def run(self, input: EngineRunInput) -> EngineRunResult:
        # 1. Create engine_run record
        run_id = await workflow.execute_activity(
            create_engine_run, input, ...)

        # 2. Resolve and pin settings
        settings = await workflow.execute_activity(
            resolve_settings, run_id, ...)

        # 3. Rule tree and replenishment — in parallel
        #    (neither depends on the other; pullback needs both)
        gate_task = workflow.execute_activity(
            evaluate_rule_tree, run_id, ...)
        repl_tasks = [
            workflow.execute_child_workflow(
                ReplenishmentWorkflow.run,
                ReplenishmentInput(run_id=run_id, dc_code=dc),
                id=f"repl-{run_id}-{dc}")
            for dc in input.dc_codes
        ]
        gate_results, *repl_results = await asyncio.gather(
            gate_task, *repl_tasks)

        # 4. Pullback — Mon/Thu only, per DC in parallel, AFTER replenishment
        if input.pullback_night:
            pullback_results = await asyncio.gather(*[
                workflow.execute_child_workflow(
                    PullbackWorkflow.run,
                    PullbackInput(run_id=run_id, dc_code=dc),
                    id=f"pullback-{run_id}-{dc}")
                for dc in input.dc_codes
            ])

        # 5. Markdown engine (needs DISCOUNT outcomes from rule tree)
        markdown_results = await workflow.execute_activity(
            run_markdown_engine, run_id, ...)

        # 6. Governance routing
        await workflow.execute_activity(
            route_lines, run_id, ...)

        # 7. Release auto lines
        await workflow.execute_activity(
            release_auto_lines, run_id, ...)

        # 8. Start review workflows for non-auto lines
        review_lines = await workflow.execute_activity(
            get_review_lines, run_id, ...)
        for line in review_lines:
            await workflow.start_child_workflow(
                ReviewWorkflow.run,
                ReviewInput(line_id=line.line_id, ...),
                id=f"review-{line.line_id}")

        # 9. Execution dispatch (Phase 0: shadow; Phase 1: CSV)
        await workflow.execute_activity(
            dispatch_execution, run_id, input.phase, ...)

        return EngineRunResult(run_id=run_id, ...)
```

### 7.2 ReplenishmentWorkflow (child, per DC)

```python
@workflow.defn
class ReplenishmentWorkflow:
    @workflow.run
    async def run(self, input: ReplenishmentInput) -> ReplenishmentResult:
        # 1. Compute targets per option × store
        targets = await workflow.execute_activity(
            compute_replenishment_targets, input, ...)

        # 2. Apply capacity caps per store × brick × grade
        capped = await workflow.execute_activity(
            apply_capacity_caps, input.run_id, input.dc_code, targets, ...)

        # 3. Size split and dispatch
        lines = await workflow.execute_activity(
            size_split_and_dispatch, input.run_id, input.dc_code, capped, ...)

        # 4. DC rationing (if DC is short)
        if any(l.needs_rationing for l in lines):
            lines = await workflow.execute_activity(
                ration_dc_shortage, input.run_id, input.dc_code, lines, ...)

        return ReplenishmentResult(lines=len(lines))
```

@workflow.defn

        return PullbackResult(...)

### 7.4 ReviewWorkflow (long-running, signal-driven)

```python
@workflow.defn
class ReviewWorkflow:
    """Handles one line's review lifecycle."""

    def __init__(self):
        self.decision: Optional[str] = None

    @workflow.signal
    async def decide(self, decision: str, decided_by: str):
        self.decision = decision

    @workflow.run
    async def run(self, input: ReviewInput) -> ReviewResult:
        if input.autonomy_band == "review_window":
            # Wait for 12h or a block signal
            try:
                await workflow.wait_condition(
                    lambda: self.decision is not None,
                    timeout=timedelta(hours=input.review_window_hours))
            except asyncio.TimeoutError:
                # Window expired, no block → release
                self.decision = "release"
        else:
            # stop_and_approve: wait indefinitely for signal
            await workflow.wait_condition(
                lambda: self.decision is not None)

        await workflow.execute_activity(
            apply_line_decision, input.line_id, self.decision, ...)

        return ReviewResult(line_id=input.line_id, decision=self.decision)
```

| Component | Configuration |
|---|---|
